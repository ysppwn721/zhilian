# 知链

知链是一个可本地运行的跨文档结论验证与增量修复原型。输入一份 Excel 事实表及 Word/PPT 成果，确认数据来源关联，更新数值后重新验证论断，预览并修复失效内容，最后导出真实 Office 文件与核验记录。

当前版本：0.2.1。已实现规则识别、证据链智能体、人工确认闭环、OCR 只读支线、诊断报告和只读 MCP 工具；模型接口为可选的来源关联助手。它不是任意文档的通用理解或全格式编辑系统。

## 快速启动

Windows 下双击 `start.bat`，或在项目根目录运行：

```powershell
.\start.ps1
```

浏览器访问 http://127.0.0.1:8765 。首次在新电脑启动需要 Python 3.11 或以上及联网安装依赖。当前工作目录已创建 `.venv`。

其他环境：

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# Linux/macOS: source .venv/bin/activate
python -m pip install -r requirements-runtime.txt
python run.py
```

`requirements-runtime.txt` 只含应用本体真正 import 的依赖（体积最小，适合信创环境）。
`requirements.txt` 是开发/评测全集，额外含 `pandas`、`pdfplumber` 与本地重排模型三项——
这些只被 `答辩评测/` 下的脚本使用，应用缺失时会自动降级，不是运行必需。
跑测试用 `requirements-dev.txt`。

未配置任何模型也可以运行。无需购买 GPU 或服务器即可在本机体验。

## 五分钟体验

1. 点击“体验演示项目”，系统生成 Excel、Word、PPT 三份模拟业务文件。
2. 点击“批量确认候选关联”，审阅主体、期间与口径并确认；也可逐项“查看依据”纠正来源。
3. 点击右侧“载入演示变更”，将销售额125改为90、A产品销量80改为60、支出80改为110。
4. 点击“更新数据并验证”。销售额、增长率、排名、预算判断与图表会出现失效项。
5. 点击“预览修复”，核对修改前后内容后确认。
6. 下载成果包，在 Word/WPS、PowerPoint/WPS 中打开。包内含源表、修改后的文件、核验报告和完整JSON记录。
7. “撤销变更”可以恢复上一次数据变更或修复之前的版本。

另一个重要例子：销售额125改为123时，“超过120万元”仍成立，不应修改；“增长25%”则需重算。单纯依赖变化不会自动变为失效。

## 导入自己的文件

### 在 Excel / WPS 中修改后更新

网页使用的是导入时的文件副本，不监听磁盘文件，也不会自动更新已经下载或打开的 Word/PPT。
在 Excel/WPS 中修改并保存 `.xlsx` 后，在原项目右侧点击“导入更新后的 Excel”，选择已保存的文件。
系统会先展示数值差异及受影响论断的预计状态；确认后才保留已确认关联、建立源表新版本并重新验证。随后点击“预览修复”并确认，再下载新版 Word/PPT。预览不会写入项目版本。
此入口要求事实ID集合及主体、指标、期间、单位、统计口径保持一致，可以修改数值或调整行顺序。
增删事实或改变含义需要重新建立项目并审阅关联。源表导入及后续修复均可以撤销。

创建项目时上传一份 `.xlsx` 和至少一份 `.docx` 或 `.pptx`，首批最多10份、合计30MB。项目创建后可在“来源与文件”点击“追加成果文档”，按批次继续加入 Word/PPT/图片；默认单批最多50份、100MB，项目总文档默认最多500份。后续批次不再上传 Excel，系统会为每批建立 revision、批次 ID 和审计记录，任何文件解析失败都会回滚整批。Excel首行必须包含下面的列，顺序可以变化：

| 事实ID | 主体 | 指标 | 期间 | 数值 | 单位 | 统计口径 |
| --- | --- | --- | --- | --- | --- | --- |
| sales_prev | 总计 | 销售额 | 上期 | 100 | 万元 | 演示业务 |
| sales_current | 总计 | 销售额 | 本期 | 125 | 万元 | 演示业务 |

事实ID须唯一、非空。可下载界面中的模板。当前对上期/本期使用明确标签；不自动推断财年、同比基期、累计范围。事实表中的公式会被拒绝，避免使用过期缓存；请提供已核实的数值。

一段文字中并列出现多个受支持表达时，系统按数值、增长率、阈值等原子论断分别建立锚点和核验结果；未被覆盖的连接词、背景说明与其他文本会在“来源与文件”中单独列出，不会因为同段另有一条通过而被默认为正确。

规则模式支持的表达举例：

- 数值：`本期销售额为125万元`。
- 增长率：`本期销售额较上期增长25%`。同一段中紧接数值引用的`较上期增长25%`也可解析。
- 定性方向：`本期销售额较上期增长`，数据变动后方向仍成立时保留原句。
- 排名：`A产品销量最高`、`A产品、B产品销量并列最高`。只对确认过的比较集合负责。
- 阈值：`本期销售额超过120万元`、`本期支出低于100万元`、`支出未超过预算`。

零基期、负基期、口径冲突、缺失数据和无法唯一匹配的来源返回“无法判断”，不会自动写入。“增长主要来自渠道优化”等因果解释不在计算验证范围。标题和未识别正文单独展示，不能算成“通过”。

## 模型方案

复制 `.env.example` 为 `.env`，在本机编辑后重启。不要在聊天、截图、前端代码或源码包里放密钥。

### DeepSeek V4.1 官方 API

后端直接请求 `https://api.deepseek.com/chat/completions`，使用现有 HTTPX，无需安装 OpenAI SDK 或配置其他服务商。根据 [DeepSeek 官方文档](https://api-docs.deepseek.com/)（2026-09-19 核对），DeepSeek V4.1 Flash 的 API 模型 ID 为 `deepseek-flash`。

部署方在 [DeepSeek 开放平台](https://platform.deepseek.com/) 创建 API Key，确认账户额度，并在服务器 `.env` 中填写：

```text
DEEPSEEK_API_KEY=填写你的真实密钥
DEEPSEEK_MODEL=deepseek-flash
```

重启服务后刷新网页。客户无需配置密钥，直接点击“DeepSeek 关联建议”，在“查看依据”中审阅建议并确认来源。首次测试应使用未确认的演示论断；已确认论断和图表不会发送。费用由部署方承担。

`/api/health` 中 `model.enabled=true` 和 `key_configured=true` 只说明服务端已读取密钥，不代表真实 API 已验证。必须成功请求一次建议才能确认连通性。请求关闭思考模式、启用 JSON 输出，用于受限的事实来源匹配。旧的 `ZHILIAN_LLM_*` 配置不再使用。

### 当前模型职责与限制

模型只为**规则已经识别的论断**提出事实ID关联建议。它不自动抽取任意自然语言论断，不自动确认、不修改文件、不执行代码。返回的事实ID必须存在；源数据口径仍由确定性程序检查，人工确认后才能修复。

发送内容是论断文本和事实元数据（主体、指标、期间、单位、口径）；不会直接上传原始Office文件，也不会发送完整事实值。请求最多40条待确认论断、150条事实，超时60秒。提供方可能从论断文本中看到业务数值，敏感文本仍需自行评估。

已实现 DeepSeek 官方直连；自动测试使用模拟 API 响应，覆盖请求、结构校验、失败处理和密钥不返回前端。真实连通性和模型质量需要部署方配置密钥后验证；确认关联后的计算正确性单独报告。

## 智能体（Agent）

“运行智能体”启动证据链验证任务：**准备 → 关联 → 诊断 → 询问（人工） → 修复 → 复核 → 完成**。首版是确定性状态机编排，不是让模型自由选择工具的 ReAct 循环。Agent 是编排器，复用 `store` / `engine` / `office` / `llm`，大模型仅作为来源关联工具，不计算、不裁决、不写文件。

导入自己的 Excel 与 Word/PPT 后，“导入识别完成”窗口会显示文件数、已识别论断数，并提供“运行智能体”和“先查看识别结果”两个入口。点击“运行智能体”后仍需在启动说明中点击“开始运行”；关闭窗口后也可从工作台顶部启动。普通导入项目与演示项目使用相同的智能体流程，无须先载入演示变更。

准备阶段检查版本、文件校验和原文锚点；关联阶段合并规则候选与可选 DeepSeek 候选；诊断阶段逐项执行 `engine.check`，展示文档位置及 Excel 单元格。来源不唯一时先请求消歧，唯一候选仍须人工确认。**勾选条目并提交来源决定后，只完成来源确认；文件修复另行预览、勾选批准。** 修复由现有 `store.repair` / `office` 实际写入工作区的新文件版本，重新读取后检查修复项及其他受支持正文。请下载新版本查看，外部原文件不会随之改动。

未配置模型也能完整运行。启用模型时，开始前提示发送范围与费用；沿用最多40条未确认非图表论断、150条事实的限制，超过事实上限或模型调用失败时退回规则候选。所有来源仍须人工核对。无法计算的来源不能确认，需手动纠正事实关联；无法判断及未识别正文不会被计作核验通过。

待办、运行 ID、诊断和执行轨迹存于项目 `state.json` 的 `agent` 字段。关闭待办窗口、刷新页面或重启服务后，点击“继续智能体待办”恢复；部分批准后其余项继续等待。等待期间重复运行不重新请求模型。外部更新数据或来源会使旧待办失效，须重新运行并审阅。首版同步执行并使用现有单进程锁，网络请求期间其他项目写操作可能等待；不是后台调度服务。

“变更记录”显示本次任务轨迹：节点、时间、中文摘要、模型 ID 和耗时，同时写入原有 audit。模型请求失败与降级会明确留痕；出现模型 ID 仅说明尝试调用，需结合“收到 N 项模型候选”或失败记录判断结果。响应和审计不保存 API Key 或外部错误原文。

新增接口（均沿用密码保护、跨站校验和禁止缓存）：

- `POST /api/projects/{wid}/agent/run`：`{"revision":当前版本}`。
- `POST /api/projects/{wid}/agent/decide`：`{"revision":当前版本,"decisions":[{"kind":"confirm_links","items":[{"claim_id":"论断ID","refs":["事实ID"]}]}]}`。kind 需匹配当前 pending，可为 `confirm_links`、`resolve_ambiguity` 或 `approve_repair`；修复只需 claim_id。每次只批准一组当前阶段的非空条目。
- `GET /api/projects/{wid}/agent/status`：只读返回 phase、pending、trace、result，并以 stale 标识待办是否过期。

扩展点位于 `zhilian/agent.py` 的 `TOOLS`。新增同签名函数 `tool(store, ws, payload) -> dict` 并注册后，在相应阶段通过 `_tool` 调用即可获得统一轨迹。未来 `analyze_ambiguity` 可接在关联阶段，`summarize` 可接在复核之后；本次未实现这两项。文件修改已通过 `repair` 工具完成；未来扩展修改能力应沿用人工批准、现有修复校验及复核，不允许模型直接写文件。

### Agent 验证方法

更新代码后停止旧服务，再运行 `start.bat`，浏览器按 Ctrl+F5。建议新建演示项目，避免干扰已有资料。

1. **离线完整流程**：临时在 `.env` 将 `DEEPSEEK_API_KEY` 留空并重启（也检查启动终端未覆盖同名环境变量），确认网页显示规则模式。创建演示，点击“载入演示变更”及“更新数据并验证”，关闭旧的来源审阅弹窗。点击“运行智能体”→“开始运行”。
2. **第一道人工确认**：应停在“审阅来源关联”。此时来源仍未确认、Word/PPT 未修改。逐项核对并勾选后，点击“确认所选来源并继续”。可只批准一部分，验证剩余条目仍待办。
3. **第二道人工确认**：应显示修复前后内容，关闭窗口并刷新，再点“继续智能体待办”，内容应保留。勾选修复项并点“批准所选修复并复核”。全部批准后，本演示预期修复11项、不一致0项。
4. **检查真实文件**：下载 Word，确认包含“本期销售额为90万元”“较上期下降10%”“B产品销量最高”“支出超过预算”，背景段落保持原文；下载 PPT，确认图表数值为100、90。通过“变更记录”检查人工决定、修复和复核轨迹。
5. **模型验证**：恢复密钥、重启，新建一个未确认来源的演示项目后运行 Agent。轨迹应出现 `DeepSeek 关联建议`、配置的模型 ID 及“收到 N 项模型候选”；官方控制台再核对用量。若为“工具执行失败”并出现“Agent 模型降级”，则这次仅完成规则流程，不能宣称模型调用成功。自动测试使用 mock，不消耗真实额度。
6. **歧义验证**：复制事实表“本期销售额”一行，赋予新的事实 ID 和不同统计口径，用它和演示 Word 新建项目。Agent 应先停在“选择有歧义的来源”，展示多个候选；选中来源并明确批准才生效。

自动回归（无需真实密钥）：

```powershell
.\.venv\Scripts\python.exe -m pytest tests/test_agent.py -q
.\.venv\Scripts\python.exe -m pytest -q
```

Agent 测试覆盖真实 Office 修改、人工闸门、消歧、部分批准、持久化恢复、幂等、过期版本、非法决定、锚点、模型调用前留痕、失败降级、错误信息脱敏及新接口的访问边界。

## WPS与文件兼容

项目读写标准 OOXML 文件，不依赖、打包或逆向WPS软件，不调用WPS SDK。WPS常用的`.xlsx/.docx/.pptx`是支持的输入扩展名；旧格式`.xls/.doc/.ppt`需另存为新格式。

已支持Word普通正文与一层普通表格；PPT普通文本框、表格和单系列簇状柱形图。文本局部替换会保留未修改run的格式，替换内容继承其首个run的格式。跨多种格式的一个论断修改后，内部格式可能合并；这不是任意排版保真的承诺。

页眉页脚、备注、母版、图片文字、组合对象、复杂域、复杂图表与宏不属于首版验证范围。WPS特有扩展、旧格式及复杂排版需要实测，不能宣称全功能兼容。项目没有接入WPS在线编辑或收费平台；以后接入需另行核对相应许可。

## 实现结构

```text
zhilian/app.py      HTTP接口、上传、密码保护、模型入口
zhilian/engine.py   规则识别、Decimal计算、单位/口径约束
zhilian/office.py   Office位置锚点、文件读写、run级修改、图表更新
zhilian/store.py    项目存储、快照、事务修复、再验证、撤销、导出
zhilian/llm.py      DeepSeek 官方 API 直连与关联建议校验
zhilian/agent.py    证据链验证智能体、人工决定、工具注册表与执行轨迹
zhilian/demo.py     可重复生成的模拟文件
web/               不依赖前端构建工具的中文工作台
tests/             引擎、真实文件、HTTP和模型适配器回归测试
.zhilian/          本地用户数据和版本，不提交源码
```

依赖图采用事实ID与论断refs关系表达；计算覆盖四类文字论断和受支持的图表。更新保存新文件版本，修复前校验文件SHA256和项目revision。修复后重新读取Office成果，要求选中论断重新验证通过、其他支持范围内的正文内容一致，失败则废弃本次新版本。该检查不替代视觉排版检查。

存储采用单进程本地JSON及文件版本，适用于原型与小团队共享演示；不要配置多个worker写同一数据目录。尚未实现多租户、角色权限、账户隔离、存储配额和自动版本清理。

## MCP 接口

知链提供一个基于官方 `mcp` Python SDK 的只读 stdio 服务，供 Claude Desktop、Cursor、Windsurf 等支持 MCP 的 Agent 调用。服务复用 Web 端的 `.env` 和 `ZHILIAN_DATA_DIR`，不会暴露写入、修复、撤销或变更工具。

启动服务：

```powershell
.\.venv\Scripts\python.exe -m zhilian.mcp_server
```

v1 提供七个工具：`list_projects` 列项目；`parse_facts` 解析 Excel 事实；`parse_document` 解析 Word/PPT 并抽取论断；`verify_claim` 核验单条论断；`verify_project` 核验项目；`diagnose_project` 生成异常分类和证据溯源；`diff_excel` 预览新 Excel 的影响且不写入项目。文件路径必须使用绝对路径，项目 ID 为 32 位 ID。失败时工具返回中文结构化 `error` 字段，返回值可直接按 JSON 处理。

Claude Desktop 等客户端的接入配置示例：

```json
{"mcpServers":{"zhilian":{"command":"C:\\path\\to\\项目\\.venv\\Scripts\\python.exe","args":["-m","zhilian.mcp_server"],"env":{"ZHILIAN_DATA_DIR":"C:\\path\\to\\项目\\.zhilian"}}}}
```

`ZHILIAN_DATA_DIR` 必须与 Web 端一致。v1 只读；写工具计划在后续版本增加，并继续沿用人工确认和版本校验。

## 本地 Reranker（可选）

知链支持可选的 ONNX INT8 本地事实来源排序模型。基础模式不需要模型；配置本地模型后，Agent 对规则多候选进行排序，并在事实表不超过 150 条时对零候选论断做整表语义召回。低置信度仍转人工或 API，不直接写入文件。

推荐模型为 `bge-reranker-v2-m3` 的 ONNX INT8 版本。模型权重约 570MB，独立放在 `models/bge-reranker-v2-m3-onnx-int8/`，不进入基础源码包。依赖为 `onnxruntime`、`tokenizers` 和 `numpy`，不需要 PyTorch。

启用方式：在 `.env` 设置 `ZHILIAN_LOCAL_RERANKER_PATH=models/bge-reranker-v2-m3-onnx-int8`，重启服务后通过 `/api/health` 查看 `local_reranker.enabled=true`。模型不可用时自动退回规则/API流程。

## 部署

本机开发默认仅监听127.0.0.1。局域网/公网需要设置：

```text
ZHILIAN_HOST=0.0.0.0
ZHILIAN_ACCESS_PASSWORD=替换为足够长的随机密码
```

登录用户名为 `zhilian`。公网使用HTTPS反向代理，不直接公开明文Basic Auth端口；API文档和下载也受同一密码保护。所有用户共享一个工作空间，不适合未经隔离的公开匿名服务。

Docker构建示例（Dockerfile已提供，本机尚未验证Docker运行）：

```bash
docker build -t zhilian .
docker run --rm --env-file .env -e ZHILIAN_HOST=0.0.0.0 -p 127.0.0.1:8765:8765 -v zhilian-data:/data zhilian
```

`.env`中需设置访问密码和服务端 DeepSeek 密钥，容器需能访问 DeepSeek 官方 API。数据卷需要备份。公网服务器、域名、HTTPS和真实模型额度需由部署方配置。
