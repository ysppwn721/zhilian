## 二、为什么把静态页和后端分开

```
zhilian.space        → Cloudflare Worker     静态站（大文件由下载接口提供）
demo.zhilian.space   → Cloudflare Tunnel  →  8.141.119.159:8765（FastAPI + 只读下载）
```

好处：

1. **服务器零公网入站端口**：安全组维持默认即可，所有流量由 cloudflared 出站建立；
   应用只监听 `127.0.0.1:8765`，公网无法直接访问。
2. **网页静态资源由 Cloudflare 边缘分发**；超过 Worker 单文件限制的安装包和本地模型由
   `demo.zhilian.space/downloads/` 的固定白名单接口提供，避免把模型塞进 Worker 资产。
3. 静态站更新与后端更新互不影响。

```bash
systemctl status zhilian cloudflared
journalctl -u zhilian -n 50 --no-pager
journalctl -u cloudflared -n 50 --no-pager
```

**更新版本：**

```bash
cd /opt/zhilian/biaoliruyi
git fetch --depth 1 origin main && git reset --hard origin/main
/opt/zhilian/venv/bin/pip install -i https://mirrors.aliyun.com/pypi/simple/ -r requirements.txt
systemctl restart zhilian
```

> 用 `git reset --hard origin/main` 而不是 `git pull`：浅克隆下 `pull` 会因历史分叉而失败。

## 五、模型调用限额（服务端付费的护栏）

演示环境用服务端密钥替使用者付费，而测试账号按大赛要求公开，因此必须限流：

| 变量 | 默认 | 含义 |
| --- | --- | --- |
| `ZHILIAN_QUOTA_PER_CLIENT` | 60 | 单个访客每日模型调用上限 |
| `ZHILIAN_QUOTA_GLOBAL` | 600 | 全局每日上限 |

- 访客标识优先取 `CF-Connecting-IP`；演示位于 Cloudflare 之后，取 socket 地址会把
  所有访客算成同一个边缘节点。
- 超限**不报错**，自动降级为规则模式，并在项目审计里记一条「模型额度用尽」。
- 计数按自然日清零，落在 `/opt/zhilian/data/quota.json`；文件损坏或不可写时按零消耗
  处理，限额模块本身不会影响演示。
- 工作台右上角与「请求 DeepSeek 关联建议」「运行智能体」弹窗都会显示今日剩余次数。

## 六、为什么保留密码保护

大赛要求「软件若设置了用户名和密码，必须在显著位置注明测试账号和密码」。
保留保护的价值：

1. **不被爬虫和陌生人误用**——演示环境开放写入（可创建项目、下载文件）；
2. **符合大赛要求**——账号已在站点和设计文档中公开；
3. **演示可复现**——评委用同一账号进入，看到一致的环境。

## 八、已注意到的风险

1. **模型不随包分发**：560 MB 的 ONNX reranker 不在仓库（GitHub 单文件限 100 MB），
   需手工上传；缺失时自动降级为规则 + API，功能不缺。
2. **数据持久化**：`/opt/zhilian/data` 必须保留；建议开每日备份（见 `deploy/backup.sh`）。
3. **密钥轮换**：`DEEPSEEK_API_KEY` 曾出现在沟通记录中，比赛结束后应到控制台轮换。
4. **突发性能实例**：不要用 t5/t6 之类共享型规格，ONNX 推理会打满 CPU 并被限频。

## 九、备选部署方式（compose + Caddy）

仓库 `deploy/` 仍保留一套 Docker Compose + Caddy 的同域方案，适用于「服务器直出整站
并自行申请 HTTPS」的场景。它与当前线上方式二选一即可，注意两者都会占 80/443。
