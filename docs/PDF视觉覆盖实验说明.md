# PDF 视觉覆盖实验

这是一个独立实验，不接入知链正式写回流程。代码位于 `zhilian/pdf_overlay_experiment.py`，使用 PyMuPDF 完成以下步骤：

1. 在指定页搜索旧字符串，取得文字边界框；
2. 读取附近文字的字号和颜色；
3. 用白色矩形覆盖旧字符；
4. 在原位置绘制新字符串；
5. 保存为新的 PDF，并重新抽取验证。

实验产物：

- `output/pdf/pdf_overlay_experiment/wps_like_original_en.pdf`：原始实验文件；
- `output/pdf/pdf_overlay_experiment/wps_like_modified_en.pdf`：只把正文 `6.04` 覆盖为 `5.80` 的新文件；
- 同名 PNG：用于视觉检查。

这个实验解释了桌面 PDF 编辑器为什么可以提供类似 Word 的体验：用户看到的是局部文字覆盖和坐标重绘，底层仍然是 PDF 内容流。它没有实现段落级重排，也没有同步修改表格。实验中正文被改成 `5.80`，表格仍保留 `604,539,544.17`，因此正好展示了知链为什么默认输出勘误表。

实验代码会返回 `layout_risk`：当新字符串估算宽度明显超过旧字符串时，标记可能遮挡后续文字。它还明确保留原文件，不处理数字签名、扫描件、字体子集和跨位置一致性。

正式产品仍应遵守 `docs/PDF安全写回说明.md` 的三档预检决策。这个实验只用于理解 WPS 类实现方式和评估视觉覆盖技术，不代表知链已经支持任意 PDF 安全写回。
