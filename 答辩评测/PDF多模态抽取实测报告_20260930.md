# PDF 表格与图表抽取实测（2026-09-30）

> 2026-10-01 更新：比例/占比指标现在按“本期比例 − 上期比例”的百分点变化校验；结构错位和不确定行仍不会进入可用事实列表。v5 重新计算并区分“可用事实”“有独立交叉校验的事实”和“交叉校验行”。

本轮目标是验证公开年报能否被安全地转换为知链事实表，并确认图表是否可以直接参与数值核验。实验只读取本地公开 PDF，不修改冻结评测集，也不把自动抽取结果写入训练集。

## 实验范围

- 40 份公开年报 PDF，合计 8,052 页。
- 文字层：PyMuPDF（`pymupdf`）。
- 表格：pdfplumber，多组表格参数择优；包含跨行表头、变动金额/变动比例区分、PDF 拆列数值修复。
- 图表：页级候选检测和页面渲染；当前不从矢量图或图片中猜测数值。
- 表格的“正确性”只用报告自带的变动比例列做结构性交叉校验，不能称为人工真值。

## 批量结果

| 指标 | 结果 |
|---|---:|
| 成功处理文档 | 40/40 |
| 具有文字层的页 | 约 99.99% |
| 进入可用事实列表 | **1,491 条** |
| 其中有独立交叉校验的事实 | **220 条（14.76%）** |
| 抽取候选财务表 | **395 张** |
| 产出事实的文档 | 39/40 |
| 带变动比例的可交叉校验行 | **132 条** |
| 交叉校验通过的表格行 | **115/132，87.12%** |
| 识别出的图表候选页 | 13 页 |
| 平均单份耗时 | **8.68 秒** |
| 中位单份耗时 | **9.05 秒** |

“39/40”不是 PDF 识别准确率：其中 1 份英文半年度报告没有中文财务关键词，文字层可读但没有进入中文财务表抽取分支。1,491 条是通过结构门槛进入可用列表的事实条目；其中 220 条能回指到报告自带的变动字段并进行独立交叉校验。132 是校验行数，不是事实条数；每个通过的表格行通常对应本期、上期两条事实，且跨摘要表与明细表去重后数量会变化。87.12% 也不是表格整体准确率，而是抽出的当前值、上期值与表内变动字段在 ±0.5 个百分点内一致的结构校验比例。

本轮通过率从旧口径的 78.10% 到 87.12%，不能解释成单纯的抽取准确率提升。其中一部分来自比例/占比指标校验定义的修复：这类指标改用“本期比例 − 上期比例”的百分点差，不再用“本期/上期 − 1”的相对变化。答辩时应完整表述为：**修正比例类指标的会计语义后，结构校验通过率由 78.10% 升至 87.12%。**

## 已修复的真实版式问题

1. 同一张表同时有“变动金额”和“变动比例”时，优先选择百分比列。
2. 中文字体映射丢失时，利用数据单元格的 `%` 后缀回找百分比列，但只接受位于上期列右侧的列。
3. PDF 把 `1,` 与 `032,869.20` 拆到相邻单元格时合并数值，同时保留原列位置。
4. 多行表头优先使用明确包含“同比/增减/变动”的表头，避免把“占营业收入比例”误当成变动列。
5. 抽取事实保留来源页、表格编号、期间、单位和统计口径；v5 的 17 条交叉校验失败行只进入审计记录，不进入可用事实列表。

6. 失败行另存为 `pdf_failure_taxonomy.csv/json`，保留来源文件、页码、表号、行号和启发式失败类别。类别用于工程排查，不是人工真值。

### 失败优先级

后续修复按“是否可能静默出错”排序，而不是按出现次数排序：

1. **单位不明确**：最高风险，可能造成 10⁴ 倍数量级错误，且变动比例仍可能自洽；
2. **表头跨行或期间列错位**：高风险，数值可能正确但归属到错误期间；
3. **负数括号和符号**：高风险，三值可能看似一致但方向错误；
4. **变动金额/变动比例列错位**：通常属于响亮失败，现有交叉校验更容易发现，可在前三类之后处理。

每个事实现在保留 `has_cross_check` 与 `cross_check_status`：有报告变动字段且计算值可得时为 `true`，否则为 `false`；状态为 `passed`、`failed` 或 `not_available`。没有独立校验的事实仍可进入候选列表，但不能被描述为“已交叉验证”。

## 词表扩充边界

本轮只加入低歧义的确定性别名，例如“营收”→“营业收入”、“总资产”→“资产总计”。“主营收入/营业总收入/销售额”等可能对应不同会计口径的词没有强行合并，而是留给本地 BGE 或 API 生成候选并要求用户确认。这样可以提高真实年报的召回，同时保留“规则负责证明、模型负责消歧”的分工。

## 图表结论

目前可以可靠地回答“哪一页可能包含图表”，并渲染页面供复核；不能仅靠 pdfplumber/PyMuPDF 从复杂矢量图或图片图表中可靠恢复类别和值。因此图表路径输出 `candidate_needs_ocr_or_review`，不会自动写入事实表，也不会自动修改 Word/PPT。这是安全边界，避免把视觉误读当成业务事实。

## 是否需要重新训练模型

本轮不建议立即微调 reranker。PDF 结构化解决的是“事实从哪里来”，模型训练解决的是“论断如何关联事实”，两者不能用同一批自动抽取标签混在一起。当前应该先把 PDF 事实保留页码和表格证据，再用其中一小部分经过复核的论断—事实对做独立 dev/test。

建议只有同时满足以下条件才开启下一轮训练：

1. 至少 500 条跨文档组的高置信论断—事实对；
2. train/dev/test 按文档组隔离，且 dev/test 不来自同一份年报；
3. 每条正例能回指页码和表格行，负例覆盖错指标、错期间、错口径；
4. 新模型在外部文档组 Top-1 提升至少 3 个百分点，且错误关联率不升高。
