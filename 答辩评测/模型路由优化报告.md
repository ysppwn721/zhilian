# 模型路由优化报告

## 目的

模型只参与语义候选建议，确定性引擎负责计算、裁决和写回 Office 文件。优化前，Agent 会把所有未确认论断整批交给 API，并用 API 结果覆盖本地结果，导致模型在规则已经唯一确定的样本上重复工作。

## 当前路由

```text
规则唯一候选 / 已解析的增长率、排名、阈值、图表
    -> 直接进入人工确认，不调用模型
规则多候选
    -> 本地 BGE reranker 排序
    -> 低置信或拒答才升级 API
规则零候选（事实表 ≤150 条）
    -> 本地 BGE 对整表语义召回
    -> 低置信或拒答才升级 API；失败则人工确认
所有来源
    -> 人工确认后，确定性引擎重新核验并修复文件
```

API 请求在项目内按最多 40 条困难论断分批，`agent.model_routing.api_batches` 会记录实际批次数。不同文档组的离线评测不能直接合并事实表，因为事实 ID 和口径必须保持组内隔离；因此跨组报告只给理论批次数下限，不把它当成实测延迟。

## 评测结果

评测文件：`model_routing_metrics.csv`、`model_routing_report.json`、`model_routing_comparison.svg`。当前 180 条是程序化夹具，30 个文档组，不能称为人工行业真值。

| 方案 | Top-1 | 错误关联率 | 歧义拒答率 |
|---|---:|---:|---:|
| 纯规则 | 100% | 0% | 100% |
| 全量本地 reranker | 40% | 0% | 100% |
| 全量 API | 60% | 33.33% | 0% |
| 分层路由 | 100% | 0% | 100% |

纯规则的 Top-1 只在 `gold_action=link` 的样本上计算，因此不能单独代表安全性。**但本批数据里纯规则并没有错误关联歧义样本**：逐条核对 `predictions_rule.jsonl`，30 条歧义样本（gold 全为 `abstain`）中纯规则拒答 30/30、链接 0 条，全样本错关联 0 条。因此上表"纯规则 100% / 0% / 100%"与"分层路由 100% / 0% / 100%"是**同一组结果**。

**必须如实说明（否则评委一问就穿）**：逐条比对 `predictions_routed.jsonl` 与 `predictions_rule.jsonl`，150 条链接完全一致，30 条歧义样本两边都是拒答（仅"拒答时保留候选 refs"与"清空 refs"的表示差异，不参与打分）。也就是说——

> 在这批夹具上，分层路由与纯规则的指标完全相同。本表**不能用来证明分层路由比纯规则更准**，它只能证明：把模型限制在困难样本上，**没有让系统变差**，并且消除了"全量 API"33.33% 的错误关联。

分层路由的价值要在**规则给不出唯一候选**的语料上才看得出来，而旧批夹具的 `zero_candidate` 为 0、`multi_local` 为 0，恰好没有覆盖这种情形。P0 更新后的线上语义演示夹具新增 1 条零候选改写句，本地 BGE 实测完成 1 次整表召回并给出 `sales_current` 候选，API 候选数为 0；低置信时再进入 API。真正的外部泛化证据仍是 36 份公开年报程序化压力集（BGE ONNX Top-1 96.18% vs BERT v2 41.32%），以及真实年报抽样的识别率缺口。**这些结果分别衡量路由行为和外部压力，不混成一个准确率。**

当前这套合成评测中，多候选样本主要是增长率、阈值和歧义夹具，复合论断本来就应由确定性规则处理，歧义样本本来就应人工确认。因此本批数据证明了“调用范围和安全闸门”有效，不能证明 reranker 已经提升了中文同义表达的召回率。后续应加入真实中文改写样本，再单独评估本地 reranker 的增量。

## 答辩可用表述

> 我们没有让模型接管计算和写回，而是用评测结果决定模型在哪些样本出场。规则已唯一确定的 83.3% 论断不调用 API；模型只处理规则无法确定的候选，低置信结果转人工。这样全量 API 的错误关联被消除，系统仍保持可解释、可审计和离线可用。

**注意不要这样说**：
- ❌"分层路由把纯规则的错误关联消除了"——本批数据里纯规则错关联本来就是 0。
- ❌"我们靠 reranker 把准确率从 65% 提到 100%"——65.71% 是 `run_rule_baseline.py` 脚本分数，不是产品引擎（产品真实路径见 `run_engine_baseline.py`，280/280）。
- ❌"歧义拒答率 100% 是我们的模型能力"——分层路由的 100% 来自"复合论断不拆给模型 + 多候选必转人工"这两条**确定性规则**；本地 reranker 单独的歧义拒答率是 100%，但它在本批夹具里一次也没被调用（`multi_local = 0`）。

✅ 可以说："我们用评测决定模型的出场范围，而不是让它接管；规则能定的不花一次调用，规则定不了的才升级，且任何模型建议都不能绕过人工闸门。"

**打分口径的一处不对称，需在报告里写明**：零候选样本被 API 链接时会记为一个 link（因为人工只会看到一个候选，确认即成立），而多候选样本的 API 建议只计为 abstain（因为产品里它必然带着 ≥2 个候选进入人工选择）。本批夹具 `zero_api = 0`，因此该不对称对本表结果**无影响**；换数据集复算时必须重申这一点。

外部程序化 holdout 另有 BGE ONNX Top-1 `96.18%` 的结果，中文 BERT v2 为 `41.32%`；这些结果仍需在报告中标注为程序化标签，不能替代人工复核。
