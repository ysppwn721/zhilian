# 真实中文年报识别率实测

> P1 更新（2026-10-01）：新增“动词后紧跟百分比”的裸增长率表达支持，例如“产量增加179.79%”。在同一份冻结样本（600165 年报第 10—45 页、580 个含数字句子）上，当前版本识别出 25/580 = **4.3%**；40 份年报同页段批量结果为 1,271/46,402 = **2.74%**。严格同批对照使用 46,402 个固定文本片段：1,089 → 1,268 个片段被识别，提升 179 个片段、**0.39 个百分点**。两项分母和文档范围不同，不能互相替代。批量结果见 `答辩评测/claim_extraction_batch_v1/report.json`，严格对照见 `答辩评测/optimization_20261001/extraction_comparison.json`。该指标是确定性抽取器覆盖基准，不是语义人工准确率。

> P0 历史记录（2026-09-26）：抽取器加入「实现、录得、共计、合计、完成、增至、高达、约为、近、累计」以及无连接词金额/数量表达。000506 年报第 10—45 页 774 条含数字句子中识别 24 条（3.1%）。该结果不是人工真值，保留用于版本对照。

> 目的：检验引擎在**真实语料**上的表现，而非项目自建合成语料
> 语料：巨潮资讯网（cninfo）2022 年年度报告，169 页，文件 3.55 MB
> 历史基线：**识别率 0.5%（3/580）**，与合成语料上的 100% 相差约 200 倍。当前版本结果见下方 P1 更新。

## 二、历史版本已修复的两类表达（0 → 3 条）

### 1. 千分位数值

真实年报普遍写作 `3,379.37 万元`，旧规则只认连续数字，因此整类数值引用全部漏掉。

```python
# 修复前
NUM = r'-?\d+(?:\.\d+)?'
# 修复后
NUM = r'-?\d{1,3}(?:,\d{3})+(?:\.\d+)?|-?\d+(?:\.\d+)?'
```

同时 `number()` 增加千分位剥离，且**仅当逗号按三位分组时才剥离**，
避免把 `1,23` 这类异常输入静默改成一个别的数。

### 2. 增长率用词变体

| 年报写法 | 旧规则 | 新规则 |
| --- | --- | --- |
| `较上期增长25%` | ✅ | ✅ |
| `同比增长25%` | ❌ | ✅ |
| `较上年增加553.21%` | ❌ | ✅ |
| `较上年减少12.5%` | ❌ | ✅ |
| `比上年上升8%` | ❌ | ✅ |

关键修正是**动词变体**：年报用「增加/减少/上升」，旧规则只认「增长/下降/持平」。
同时补上方向词映射，否则会把"减少"读成"增长"——这类错误比漏识别更危险。

## 三、仍存在的缺口（实测样例）

以下是真实年报里的数值表达，其中“裸增加+百分比”已在 2026-10-01 补齐；其余仍是当前缺口：

| 样例 | 缺口原因 |
| --- | --- |
| `营业收入占比已超过公司全部营业收入的50%以上` | 算子与数值之间隔着长定语 |
| `本期毛利率低于去年同期` | 与历史期间比较但无数值 |
| `生物基、淀粉基新材增加187.44` | 表格残片，无单位 |

其余缺口已写入 `tests/test_real_phrasing.py`，以"断言识别不到"的形式固定；已补齐的裸增长率则由正向回归用例锁定。
一旦后续补齐，测试会失败并提醒同步更新文档与评测口径。

## 四、对训练数据与评测口径的影响

### 1. 合成语料的定位必须改口径

`real_eval_dataset.jsonl`（280 条）来自**确定性引擎重放**，其语料按引擎规则撰写。
它只能验证**实现正确性与回归**，**不能用于报告识别率或泛化能力**。

建议在设计文档与答辩材料中明确写成：

> 280 条为可复现回归夹具（fixture），用于验证实现一致性；
> 真实语料识别率单独实测，见本节数据。

### 2. 训练对来源的建议

从年报构建中文训练对时，**不能直接复用引擎规则**去标注——
0.5% 的识别率意味着规则根本标不出真实语料的样本。

正确做法：

1. 从年报**表格**抽事实（表格抽取已验证可行，见下节）
2. 用**人工或大模型**标注叙述文字中的规格化论断
3. 训练对由"人工确认的论断 + 表格事实"构成

### 3. PDF 表格抽取已验证可行

同一份年报的表格抽取结果（`pdfplumber.extract_tables()`）：

```
第 13 页表: 科目        | 本期数          | 上年同期数      | 变动比例（%）
            营业收入    | 604,539,544.17 | 248,717,404.89 | 143.06
            营业成本    | 604,030,284.29 | 330,631,103.93 | 82.69
```

**结构规整，可直接映射为引擎的事实表**（主体/期间/数值/单位）。
且「变动比例」列可用来**独立校验**引擎算出的增长率——这是很好的交叉验证素材。

.\.venv\Scripts\python.exe -m pytest tests/test_real_phrasing.py -q
