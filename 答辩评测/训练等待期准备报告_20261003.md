# 轻量中文候选模型：训练等待期准备报告

更新时间：2026-10-03

## 当前数据结论

当前没有可以安全启动正式微调的任务标签，不能把候选数或公开句对数量写成“已完成训练集”。

| 数据层 | 数量 | 状态 | 用途 |
| --- | ---: | --- | --- |
| 新年报 staging | 81 条 | 待审，`label=null` | 等待主体、单位、期间、口径和正负候选审计 |
| 新年报切分 | train 73 / dev 4 / test 4 | 仅按公司预切分 | 不能直接训练，dev/test 太小且未标注 |
| 旧年报对 | train 285 / dev 48 / test 51 | 已隔离，不准训练 | 存在冻结集复用、公司泄漏、“总选本期”100% 捷径 |
| 公开中文辅助集 | 约 35.8 万条 | 已核验许可 | 只做通用中文语义预适配或拒答门控 |
| 基础模型 | 8.77M 参数，权重约 35.2 MB | 已离线加载 | `uer/roberta-mini-wwm-chinese-cluecorpussmall`，尚未微调 |

合并语料目录 `annual_reports_merged` 现有 184 份、184 家公司，包含此前 50 份与新增 134 份。独立文件级验收通过后，全量候选统计为 4,269 条，其中 140 条进入“可用候选”清单（增长率 86、本期引用 54），难负例池 960 条；其余为表格独有事实或拒答候选。140 条目前全部 `label=null`，因此正例数量仍为 0，不能把 140 条称作已标注训练样本。

对 140 条可用候选做保守自动分流：18 条因三值计算不一致或变动列疑似金额而进入拒答/弃答，119 条因口径未标明、单位缺失或文本匹配较弱而进入复核队列，3 条证据字段齐全但仍等待正负标签。该分流只产生审计状态，不产生训练标签。

随后重新读取 140 条候选的事实页前后页，发现 55 条出现“分部/分产品/分行业”等线索，16 条出现“合并”线索，但这些词可能只是正文讨论或合并范围变更，并不能单独证明候选事实的口径。因此全部保留为“需要表格标题确认”，没有自动改写 scope。

因此当前不需要继续盲目下载更多年报。下一步应完成现有 184 份的口径、单位、期间和正负候选审计；只有实际确认正例不足 300 条时，才补采语料。

## 新数据到达后的固定流水线

1. 独立核验年报清单、公司去重、SHA-256、文字层和冻结公司排除。
2. 保留正文锚点；表格中没有正文引用的行不自动当正例。
3. 审阅主体、指标等价关系、单位、期间、合并/母公司/分部口径。
4. 每个论断至少保留一个正确事实和一个难负例；增长率必须保留本期与上期来源集合；无法确认时标 `abstain`。
5. 按公司隔离 train/dev/test，检查四条阻塞原因。
6. 用 `promote_approved_pairs.py` 标准化为训练格式；只有它返回 `ready_for_training=true` 才能调用训练器。
7. 训练后固定比较规则、冻结基础模型、仅训练分类头、轻量微调模型和 BGE，并记录 Top-1、错误关联率、覆盖率、拒答率、CPU 延迟、显存和模型体积。

候选抽取器已增加两项只影响召回、不赋标签的修复：保留跨 PDF 换行的短窗口，以及从“2023 年/2022 年”表头推断本期/上期列。修复前同一批 10 份得到 0 条候选；修复后得到 558 条，仍需审计确认。

## 准入命令

当前 staging 应当失败，且不能创建输出目录：

```powershell
.\.venv\Scripts\python.exe `
  答辩评测\promote_approved_pairs.py `
  --source 答辩评测\annual_report_training_staging_20261003 `
  --out tmp\promoted_pairs
```

失败原因至少包括：源 manifest 未批准、标签为空、候选集不完整或缺少训练器所需的 `claim_id/group_id`。这是保护措施，不是训练失败。

收到新数据并完成审计后，使用新的输出目录运行：

```powershell
.\.train-cuda-venv\Scripts\python.exe `
  答辩评测\promote_approved_pairs.py `
  --source <已批准数据目录> `
  --out <标准化数据目录>

.\.train-cuda-venv\Scripts\python.exe `
  答辩评测\train_reranker.py `
  --train <标准化数据目录>\train.jsonl `
  --dev <标准化数据目录>\dev.jsonl `
  --test <标准化数据目录>\test.jsonl `
  --model models\chinese_roberta_mini_wwm_base `
  --output models\zh_reranker_mini_ft
```

## 目前已验证的环境

- `torch 2.11.0+cu128`
- `transformers 5.17.0`
- `torch.cuda.is_available() = True`
- GPU：NVIDIA GeForce RTX 5060 Laptop GPU
- 基础模型可以 `local_files_only=True` 离线加载

## 训练是否值得继续的判据

轻量模型只有在两个独立条件都满足时才进入可选下载包：

1. 在未微调基础模型和独立公司测试集上有可重复的能力提升；
2. 模型体积与 CPU 延迟显著优于现有 BGE。

只满足一个条件时保留为研究对照；两个都不满足时保留 BGE，并把负结果写入实验报告。未通过标签和切分审计前，不启动训练、不修改正式评测集。
