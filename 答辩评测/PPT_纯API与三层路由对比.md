# 纯 API 与三层路由对比（PPT 素材）

## 一、同一语义集的真实 API 回放

评测集为 72 条中文语义改写论断，事实表固定，gold 为程序化标签，仅用于同集对照，不是人工行业真值。纯 API 结果来自已完成的 DeepSeek 实际调用；三层结果将同一批 API 答案放回当前生产路由：规则唯一项直接采用规则，本地 BGE 处理语义候选，API 只处理低置信难例。

| 方案 | Top-1 | 错误关联率 | 覆盖率 | 拒答率 |
|---|---:|---:|---:|---:|
| 纯 API | **83.33%** | **0.00%** | 83.33% | 16.67% |
| 规则 + 本地 BGE + API | **90.28%** | 5.56% | **95.83%** | 4.17% |

### 怎么解释

- 三层路由 Top-1 比纯 API 高 **6.95 个百分点**，覆盖率高 **12.50 个百分点**。
- 纯 API 在这批样本上更保守，错误关联率为 0，但拒答更多。
- 三层路由用本地 BGE 扩大语义召回，因此覆盖更高；代价是引入少量错误关联，仍需人工确认来源。
- 这不是“模型越多越安全”，而是“本地模型提高覆盖，API 保留为难例兜底”，两者要同时看准确率和错误关联率。

## 二、大批量文本的上游用量与费用

使用 280 条长文论断做生产端批量仿真，按每批最多 40 条、同一 DeepSeek 单价（输入 1 元/M、输出 4 元/M、未命中缓存）计算。规则和本地 BGE 的推理不产生 API token。

| 方案 | 送 API 的论断 | API 批次 | 输入 token | 输出 token | 每份报告上游费用 |
|---|---:|---:|---:|---:|---:|
| 纯 API | 280 | 7 | 12,303 | 10,288 | **0.053455 元** |
| 规则 + 本地 BGE + API | **48** | **2** | **2,115** | **1,584** | **0.008451 元** |

三层路由的输入 token 约减少 **82.8%**，输出 token 约减少 **84.6%**，API 批次从 7 批降到 2 批，单份上游费用约减少 **84.2%**。

| 年处理量 | 纯 API | 三层路由 | 预计节省 |
|---:|---:|---:|---:|
| 1,000 份 | 53.46 元 | 8.45 元 | 45.00 元 |
| 10,000 份 | 534.55 元 | 84.51 元 | 450.04 元 |
| 100,000 份 | 5,345.50 元 | 845.10 元 | 4,500.40 元 |

### 答辩口径

> 我们不把这个结果说成产品售价优势，而是在同一模型、同一单价下比较上游 token 用量。纯 API 把 280 条论断全部送到云端；三层路由先用规则和本地 BGE 处理，只把 48 条困难论断分成 2 批送 API。单份报告的金额很小，但在大批量场景会按报告数近似线性累积，因此分层路由确定性地减少 API token、调用批次和数据出域量；端到端延迟需要在同一批输入上重新实测，当前文件不把延迟下降写成已验证结论。

## 三、口径限制

1. API 结果是实际 DeepSeek 回放；本次报告未重新发送网络请求，密钥没有写入任何文件。
2. 72 条语义集的 gold 是程序化标签，不能表述为行业泛化准确率。
3. 费用按示例单价计算，不是知链产品定价，也不与 UpSlide 等产品做终端价格比较。
