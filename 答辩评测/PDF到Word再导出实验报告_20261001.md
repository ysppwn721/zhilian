# PDF 到 Word 再导出实验报告

## 实验目的

验证“PDF 生成可编辑 Word，确认修复后再导出独立修订版 PDF”能否作为知链的 PDF 交付路线，并与当前坐标重建器比较分页和版式表现。

## 实验材料

- 文档：公开年报 `000506_2023年年度报告更正后.pdf`
- 原始页数：183 页
- 原始 PDF：保存在 `output/pdf/pdf_office_export_real_000506_2023_layout_final/00_原始PDF.pdf`
- 验证方式：Word 导出 PDF 后，用 PyMuPDF 重新读取页数和文字层；代表页渲染为 PNG 做视觉对照。

## 结果

| 路线 | 转换耗时 | 导出后页数 | 结论 |
|---|---:|---:|---|
| 当前坐标重建器 → Word → Word PDF | 11.328 秒 + 4.197 秒导出 | 268 | 文字可读，但分页变化明显，不能作为版式保真结果 |
| `pdf2docx` → Word → Word PDF（前 20 页） | 约 6.06 秒 | 20 | 表格和多栏排版接近原稿，适合快速对照 |
| `pdf2docx` 纯转换（完整 183 页） | 约 68.28 秒 | - | 仅测转换器本身，不含事实抽取和 Office 导出 |
| `pdf2docx` → 知链证据包 → Word PDF（完整 183 页） | 74.525 秒 + 5.102 秒导出 | 184 | 包含表格解析、事实候选、论断候选和导出；版式明显优于当前重建器，但仍有 1 页差异 |

### 严格视觉一致性验收

新增逐页渲染比对器，在 72 DPI、零像素容差下比较原 PDF 与重导出 PDF：

| 后端 | 验收状态 | 变化页数 | 文字层完全一致 |
|---|---|---:|---:|
| native | `needs_visual_review` | 268 | 不适用，页数已变化 |
| `pdf2docx` | `needs_visual_review` | 184（其中原文对应页 183 页） | 1 / 183 |

`pdf2docx` 的共同页像素差异中位数约为 **12.81%**，最大为 **100%**。这证明它在页数和表格结构上明显优于 native，但仍然不是“零偏差复制”。知链现在把视觉比对作为修订版 PDF 的硬门：只要页数、文字层或像素渲染存在差异，产物就标记为 `needs_visual_review`，并向用户列出页码和差异区域。

完整实验产物位于 `output/pdf/pdf_conversion_benchmark_20261001/`，其中：

- `pdf2docx_full_183pages.docx`：可编辑 Word 对照稿；
- `pdf2docx_full_183pages_word_export.pdf`：Word 重新导出的独立 PDF；
- `pdf_conversion_comparison_20261001.json`：页数、耗时和 SHA-256 对比；
- `full_preview/`：原 PDF 与对照 PDF 的代表页渲染图。
- `output/pdf/pdf_backend_comparison_20261001/pdf2docx_visual_fidelity_72dpi.json`：逐页视觉和文字差异报告；
- `答辩评测/verify_pdf_visual_fidelity.py`：可复现的严格验收命令。

## 工程结论

1. 直接修改原 PDF 仍不作为默认路线。签名、权限、字体子集、表格和图表联动会让“改成功”很难证明。
2. PDF→Word→PDF 是可行的独立修订路线，但必须把“可读”与“版式保真”分开。页数变化、文字层缺失或视觉异常时只能交付 Word/Excel、原 PDF 和勘误报告，不能标记为已完成 PDF 修订。
3. `pdf2docx` 值得保留为 born-digital PDF 的可选后端；默认主链路仍使用可审计的坐标重建器。服务器可设置 `ZHILIAN_PDF_DOCX_BACKEND=pdf2docx` 显式启用。它的源码位于当前虚拟环境的 `site-packages/pdf2docx`，版本 0.5.13，MIT；上游已声明不再由 Artifex 主动维护，项目已保留许可证副本。
4. 所有 PDF 论断必须保留原始页码、坐标、原文片段和 PDF SHA-256。Word 只是修订源文件，不能替代原始 PDF 证据。

## 论断抽取审计

在同一份冻结年报上重新运行审计脚本，按句末标点统计含数字句子，避免把字符数误当作句子数：

| 指标 | 结果 |
|---|---:|
| 含数字句子 | 2,955 |
| 识别到论断的句子 | 88 |
| 论断候选 | 125 |
| 候选覆盖率 | 2.978% |
| 进入安全复核队列 | 125 |
| 已确认误抽取数 | 待人工复核 |

“进入安全复核队列”是保守审计标记，不能直接称为误抽取数。复核队列位于 `答辩评测/claim_extraction_audit_000506_20261001/claim_audit_queue.csv`；在没有人工金标准前，不把疑似风险数写成准确率或误抽取率。

## 与普通在线转换服务的可验证差异

本实验没有把“网上能转 DOC”当作竞争优势，也没有把第三方网站当作黑盒上传对象。公开 PDF 转 Word 产品的共同交付目标是格式转换；本次只做能力口径对照，不冒充第三方网站的性能测试：

| 能力 | 普通在线 PDF 转 Word 服务 | 知链当前交付 |
|---|---|---|
| 格式转换 | 通常返回 DOC/DOCX | `pdf2docx` 优先，缺失时回退 native |
| 原件证据 | 依赖用户自行留存 | 原 PDF 只读保存、SHA-256 和页码坐标锚点 |
| 表格数据 | 通常停留在 Word 表格 | 结构化为候选 Excel，并记录表格行和校验状态 |
| 论断与事实关系 | 不属于转换服务范围 | 生成论断候选 JSONL，进入规则、本地模型和 API 分层关联 |
| 数值裁决 | 不属于转换服务范围 | 由确定性引擎计算，用户确认后才修复 |
| 可追溯修订 | 通常只有下载文件 | 变更报告、确认记录、独立修订版 PDF 和重新读取验证 |
| 数据边界 | 本次未上传第三方网站验证 | 本地转换可不上传原 PDF；远程模式只发送限定字段 |

因此可对外表述的优势是“转换后的证据链和业务闭环”，不是声称知链重新发明了 PDF 转换算法。

## 已实现接口

- `zhilian/pdf_revised_export.py`
  - `export_pdf_to_editable_docx`
  - `export_docx_to_pdf`
  - `verify_revised_pdf`
  - `build_revised_pdf_manifest`
- `POST /api/projects/{id}/pdf-revised`：由当前 Word 生成独立修订版 PDF；
- `GET /api/projects/{id}/pdf-revisions/{index}`：下载修订版 PDF；
- `GET /api/projects/{id}/pdf-revisions/{index}/manifest`：下载转换和验证清单。

原 PDF 不覆盖，修订版单独存放并记录哈希。网页端 PDF 项目的“来源与文件”页提供生成按钮。

## 当前限制

- `pdf2docx` 需要额外安装，扫描件和复杂图表仍需 OCR/视觉复核；
- Word 导出使用本机 Microsoft Word，Linux/macOS 需要 LibreOffice；
- 页数一致不是完整视觉保真的充分条件，最终交付仍要查看代表页和表格；
- PDF 图表不会自动猜数值，仍以候选复核为准。
