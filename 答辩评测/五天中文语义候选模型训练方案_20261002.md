# 五天中文语义候选模型训练方案

更新日期：2026-10-02。

本方案以本日用户补充的三个条件为准：目标为 20-60 MB 量级的轻量离线候选；四条 `blocking_reasons` 全部保留；先修复 `always_current_top1=1.0` 的基准捷径，再启动训练。资料搜集由 DeepSeek 进行，本机暂不启动新训练。

## 结论与训练目标

建议重新训练一版本地中文候选模型，优先解决现有训练集的模板重复、语义覆盖不足和标签质量问题。小模型训练耗时通常不是唯一约束；可追溯训练对、正确的难负例和独立验收才是本轮重点。没有达成验收条件时继续使用 BGE 默认模型。

训练任务保持为中文论断与事实元数据的关联排序。模型输入为原文论断和 `subject/metric/period/unit/scope`，事实数值不进入候选文本。单位换算、增长率、最终裁决、修复内容生成和文件写回仍由确定性程序完成。

候选模型的两条验收线必须同时满足：能力上，相对明确界定的未微调基础模型在独立测试上有可重复提升；代价上，模型包达到 20-60 MB 量级且同机 CPU 延迟显著低于 BGE。只有两条都满足才能接入可选下载包。只满足一条时作为研究对照；两条都不满足时保留默认 BGE 并报告负结果。无需以超越 BGE 准确率作为目标。

## 现有证据

现有中文 BERT v2 在旧合成冻结测试上 Top-1 为 100%，在 72 条程序化语义改写集为 54.17%，在 36 份公开年报程序化外部压力集为 41.32%。现成 BGE 对应后两组分别为 87.50% 和 96.18%。这说明旧模型存在明显泛化缺口，但不能把两套程序化基准称为人工行业真值。

当前机器有 RTX 5060 Laptop GPU，显存约 8 GB；项目 `.venv` 中安装的是 CPU 版 PyTorch，`torch.cuda.is_available()` 为 false。训练应使用单独的 CUDA 环境并验证真实张量运算；系统安装了 CUDA 或有 NVIDIA 显卡，不代表当前 PyTorch 会使用 GPU。应用推理包继续使用 ONNX Runtime，不引入训练依赖。

## 本轮探索实验审计

本次做了短试训，生成了独立目录下的实验权重，但该版本不能用于部署或公开效果报告。

初步数据共 95/16/17 条训练、开发、测试论断。训练集实际只有 50 条未经改写的原句，其他来自改写扩增；20 个训练报告组实际属于 10 家公司。发现的问题如下：

1. 训练来源使用了现有冻结外部评测的 20 份年报。该候选模型不能再使用这套完整外部集声称独立泛化。
2. 公司 300149 同时出现在训练与开发，公司 600165 同时出现在开发与测试。按报告文件切分不足以阻止同公司跨年重复。
3. 候选主要是同一指标的不同期间，而本期总为正例。“始终选择本期”基线在三个划分上均为 100%，模型分数没有证明语义能力。
4. 增长类论断通常需要两条事实，仅比较 Top-1 会忽略是否找全来源集合。
5. 正文可能说某业务板块，而候选标为公司合并口径。原句可定位并不证明标签、口径、年份或单位正确。
6. 自动把“营业收入”替换成“销售收入”不保证在所有行业中含义相等；同义改写需要保留来源并审核，不能标作 PDF 原文。

实验权重的 `candidate_validation.json` 已标为隔离研究产物；原始训练记录保留供追溯。当前默认 BGE 和正式运行配置未切换。

## 数据准入

从新的、来源与用途允许的公开年报或中文业务文档获取训练数据。冻结评测集及其同公司跨年、更正版本不得进入本轮训练。每份资料保留公开 URL、公告时间、文件哈希、允许用途说明；原始公开 PDF 不默认进入分发包。

每条训练记录至少包含以下信息：

- 正文原句、来源页码和文字层坐标，跨行原句应保留完整上下文。
- 事实的表格页、表号、行、列、单位、期间和口径，以及原始单元格文本。
- 配对标签与标签依据，例如正文数值与表格在单位换算和显示精度下相符。
- 原句还是扩增句；扩增句回指原句，但不得计作新增独立文档或人工标注样本。
- 对多个指标、子公司/板块、追溯重述、单位不明、无年份上下文的记录，保留为待复核候选，不自动赋正确标签。

正文与表格数值一致只是关联证据之一。表格内部三值校验也不能证明单位、主体或期间归属正确。模型可辅助筛选和提出改写，但不能独自提供评测真值。

先取得数百条高质量原始论断，检查行业、主体、期间、句式、指标和口径分布，再决定扩量。样本数量是目标，不是质量保证。3-5 个有效难负例比几十个显然无关的随机负例更有价值。

## 难负例和评测设计

同时覆盖错指标、错主体、错期间、错口径、相近单位，以及没有可用来源的拒答样本。不得假设单位不同就是负例：元与万元在换算后可能是同一事实。不得假设所有“营收”“主营收入”“营业收入”均可互换。

训练、开发、测试按公司隔离；同一公司的所有年份、报告修订版和语义改写留在同一划分。开发集用于早停、温度/分数校准和路由阈值选择，测试集不参与选模型或调阈值。既有外部评测保留，新增独立真实文本评测单列。

验收至少比较：

- 未微调的基础模型、现有 BERT v2、现成 BGE、本轮候选模型。
- Top-1、候选覆盖率、错误关联率和弃答率；歧义样本单列。
- 多事实论断的来源集合完整率与集合精确匹配率。
- 各行业和难负例类别的分项结果，以及“总选本期”等简单基线。
- 同机 CPU 批量推理延迟、权重/模型包体积、ONNX 导出前后效果。

弃答不得算成错误关联。错误关联率报告采用“错误建议数 / 全部待评论断数”，同时补充“错误建议数 / 已给出建议数”以说明接受样本风险。

## 模型路线

主候选为 `uer/roberta-mini-wwm-chinese-cluecorpussmall`，4 层、隐藏维度 256；备选为 `uer/chinese_roberta_L-6_H-256`。本日核对 Hugging Face 官方仓库文件大小分别为 35,184,327 与 41,515,079 字节，均为预训练 FP32 文件，不是已微调或已量化产物。既有 12 层中文 BERT 只保留历史对照，不作为本轮交付目标。

候选按论断分组训练或采样，明确处理多正例，不能让两个正确事实互相充当负例。采用少量轮次并在开发集早停，避免再用同质化样本反复训练。

“未微调基础模型”不得用随机初始化的分类头作唯一基线，否则训练出非随机分类器就能显得提升。至少加入冻结预训练编码器的相似度排序；再补一个冻结主干、仅训练同结构分类头的基线。各组使用相同训练资料和独立测试，报告微调主干是否有增量。

如果数据与基线有效且仍有时间，再考虑通过 BGE 蒸馏获得轻量模型。BGE 软分数可以辅助训练，但最终评测必须有独立标签，否则只能证明候选在模仿教师。只有 ONNX INT8 的 BGE 文件不能直接进行 PyTorch 微调；微调原 BGE 还需要可训练权重与额外显存评估。

通过验收后导出 ONNX，再做 INT8 量化，单独比较量化前后准确性和 CPU 延迟。每个模型独立校准 raw-score 和 margin，不能沿用 BGE 阈值。候选作为可选下载包接入，本地模型缺失时仍可回退规则或用户选择的 API 模式。

## 四条阻塞检查不变

1. `company_leakage_between_splits`：同公司跨年、不同修订版和改写不得跨划分。
2. `frozen_evaluation_source_reused_for_training`：冻结外部集中的全部公司均排除，而不只排除本次发现的 20 个文件。
3. `current_period_selection_shortcut_scores_100_percent`：不允许“始终选本期”在新测试中满分；通过真实上期论断和错误候选修复，不能改低阈值或屏蔽检查。
4. `label_scope_and_period_audit_not_approved`：正文与事实的主体、口径、期间、单位尚未通过审计时，不得因为文件来自真实年报就解除阻塞。

新样本尚未交付，本条文档更新只确认目标、模型选型和构造要求；不能表述为真实新基准已通过验收。
