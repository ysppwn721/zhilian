这些是中文预训练编码器，不是已具备知链关联能力的成品 reranker。需加入分类或排序头，用“论断 + 事实元数据”成对训练。本项目输出为候选事实排序和弃答，不输出数值或直接修复文件。

本机只根据相同配置实例化两类分类模型并计数：4 层版本约 876.6 万参数，6 层约 1034.6 万参数。该检查没有加载预训练权重，不构成准确率或速度实验。主候选采用中文全词掩码预训练，但这不能预先证明它在财务任务上优于其他模型。

## 文件体积口径

以上为官方 `pytorch_model.bin` 的实际字节数，按 1 MB = 1,000,000 字节换算，不是量化估算，也不是最终安装包体积。

最终量度应分四项：ONNX 权重与外部数据文件合计、tokenizer/配置、可选模型压缩包、共享推理依赖。现有 ONNX Runtime、numpy、tokenizers 可以复用，但首次安装推理依赖仍占空间，不能把“35 MB 模型”说成“35 MB 完整应用”。

本机默认 BGE INT8 ONNX 文件为 569,705,899 字节，模型目录合计为 586,792,485 字节。网上所称 543 MB 常使用 MiB 或不同版本；比较时统一字节单位和同一计数范围。

先验判断：4 层和 6 层候选的 FP32 预训练文件已在目标范围内，没必要为追求最小体积强行量化。后续实测 ONNX FP32/INT8，选择同时满足效果、兼容性和 CPU 延迟的产物。不能用参数量推定 CPU 加速倍数，也不能假定 INT8 必然更快。

## 先修评测构造

当前隔离数据不能继续训练，四条阻塞原因保留。新基准应具备以下结构：

1. 单事实论断中同时存在真实本期引用和上期引用，不由脚本把本期统一指定为正例。
2. 候选包含错指标、错主体和错口径，不能只有同指标的三个年份。
3. 同一论断的候选顺序与标签无关，并对改变候选排列后的结果做一致性检查。
4. 无匹配、口径不明确、多来源需求单列；增长类使用来源集合完整率与集合精确匹配，不能仅看 Top-1。
5. 简单基线至少包含总选本期、总选上期和总选第一个；按题型和行业分别报告。
6. 仅在独立开发集调整采样与阈值。测试集一旦冻结，不能为了降低捷径基线或让模型胜出而删改样本。

“always current 不再满分”是最低检查，不代表新基准已足够好；还要验证标签和候选是否对应同一口径。

## 两条验收线

能力线：与未微调的同一基础编码器相比，在独立公司测试中有可重复提升；同时报告错误关联率与弃答，不能只报告最高一次 Top-1。主对照是冻结编码器相似度，补充冻结编码器仅训练分类头，避免用随机头的低分构造轻易胜出的对照。

代价线：可选模型包达到 20-60 MB 量级，并在同机、相同候选数量、相同线程数/批量/长度限制下显著降低 CPU 延迟。至少报告冷启动、预热后中位数、P95 和峰值内存，包含 tokenizer 耗时。FP32 和 INT8 分开测。

| 结果 | 处置 |
| --- | --- |
| 两条均满足 | 进入可选下载包；仍保留 BGE 默认 |
| 只有一条满足 | 研究对照，不公开为合格候选 |
| 两条均未满足 | 保留 BGE，报告小模型失败的消融证据 |

每个模型单独用开发集校准阈值，不能复用 BGE 的 raw-score 门槛。没有取得来源确认的建议不会自动写回。
