# PDF 严格一致性与下一步优化计划

## 当前结论

PDF 不能像 Word 一样通过“改一个字符”保证版式不变。`pdf2docx` 可以提高可编辑 Word 的版式质量，但 PDF→DOCX→PDF 仍会经过 Word 排版引擎重排。因此，正式交付必须把“可编辑”与“视觉一致”分成两个判据：

- 原始 PDF 永远只读保存；
- 可编辑 Word 只作为修订源文件；
- 修订版 PDF 必须逐页比较页数、文字层、页面尺寸和渲染像素；
- 任意差异都标记 `needs_visual_review`，网页不提供正式下载；
- 用户可下载转换清单和差异报告，决定是否人工处理。

## 当前基线

在 40 份公开年报、全量 183 页范围的冻结批量基线上：

| 指标 | 当前结果 |
|---|---:|
| 含数字句子 | 211,998 |
| 识别句子 | 3,270 |
| 识别覆盖率 | 1.5425% |
| 论断候选 | 4,027 |
| 统计性质 | 规则覆盖率，不是语义准确率 |

单份 183 页年报的严格视觉验收结果：183 个原文对应页中只有 1 页文字层完全一致，像素差异中位数约 12.81%，并产生 1 个额外页面。

## 下一步优化顺序

### P0 表格结构化和静默错误防线

优先处理会导致“数值看起来合理但含义错误”的问题：

1. 单位从表题、表头、脚注和行标签联合解析；单位未知时不进入可用事实；
2. 识别负数括号、负号和会计格式；
3. 合并跨行表头，区分本期、上期、期末和期初；
4. 记录 `has_cross_check`、`source_page`、`source_table`、`source_row` 和 `validation_status`；
5. 对无独立校验的事实只输出候选，不自动进入修复链。

验收要求：每类静默错误增加最小回归样本，错误必须进入复核队列，不能静默通过。

### P1 真实年报论断抽取

当前主要瓶颈不是 Word 生成，而是正文中的论断覆盖率低。下一轮按冻结语料逐组扩充：

- 数值连接词：实现、录得、共计、合计、完成、增至、高达、约为；
- 无连接词写法：营业收入 125 万元；
- 增长表达：较上年增加、同比减少、由 A 增至 B；
- 表格残片：先通过表格结构恢复指标名和单位，再进入论断关联。

每次变更固定记录：含数字句子、识别句、候选数、疑似风险数和人工确认误抽取数。没有人工金标准时，只能报告覆盖率和复核队列，不能声称准确率。

### P2 图表和扫描件

接入 OCR/视觉模型只生成图表候选、类别和值及来源页，不直接写入事实表。只有用户确认并且存在单位、主体、期间和口径时，才允许进入事实源。

### P3 正式修订交付

修订流程保持：

```text
原始 PDF 只读
  → Word / Excel 中间文件
  → 用户确认事实和修订项
  → 独立修订版 PDF
  → 逐页严格视觉验收
  → 通过才允许正式下载
```

如果业务必须做到像素级一致，后续应研究“原 PDF 页面保留 + 局部受控叠加”的专用路线；这与生成可编辑 Word 是两条路线，不能混为一个承诺。

## 不采用的做法

- 不直接修改 `site-packages` 中的第三方 `pdf2docx`；
- 不把页数一致当作版式一致；
- 不把规则安全旗标称为误抽取率；
- 不把生成的 Word 称为已经修复了原 PDF；
- 不在没有来源页、单位和口径时自动改写数字。
